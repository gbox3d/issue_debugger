## 개발 심사와 기록 규칙

- 2026-11-18 문서 확정 규칙: 사용자 요청에 따라 독립 에이전트 3명이 동일 후보를 평가하고, 서로의 표를 보기 전에 찬반·점수·근거를 제출한다. **찬성 2명 이상**이면 다수결 통과다. 이 문서 심사는 이전 개발 목표의 점수·반복 횟수와 별개이며 [문서 심사 기록](../docs/documentation_review_20261118.md)에 남긴다.

- 2026-11-15 개발 종료 상태: **자동 기사 검색 새 목표 달성·운영 검증 완료**. 11월 18일에는 128개 테스트와 임시 경로 빌드만 재검증했으며 새 운영 확인은 하지 않았다. 정식 1차 6.8 미통과 후, 같은 2차에서 후보 8.3 → 운영 확인 후 최종 **8.4/10 통과**로 확정했다. 심사 **2/3**, 3차 미사용. 개선 뉴스 3/5·UI 2/5·통합 3/5·캐시 2/5. 이전 중단 2회는 별도 이력이다. 점수·소수 사례를 전체 정확도로 표현하지 않으며 핵심 3개 범위와 반증 미완료 보류를 유지한다. [반복 대장](../docs/article_search_goal_20261115.md)과 내용을 최소화한 기술 감사 기록(UUID는 조회에 연결될 수 있음)을 기준으로 읽는다.
- 일반 작업물은 root 검증 **8/10 초과**, 개선 작업별 최대 5회다. 독립 목표 심사는 **7/10 초과**, 최대 3회다. 경계값인 8점·7점은 각각 통과가 아니다.
- 근거/결과 캐시, 중복 AI 호출 절감, 사용량 측정/회귀의 3개 효율 작업은 각각 **7/10 초과**를 요구한다. 최대 5회 개선 후 정체되면 해당 작업을 중단하고 사용자와 상의한다.
- 최신 지시가 이전 적합성 6점 이하 중단·7점 이상 재개 절차를 대체한다. 이전 점수·중단·초기 실패를 삭제하거나 새 목표 완료 근거로 재사용하지 않는다.
- 계획·구현·실측 결과를 구별하고, 미수신 점수나 미실행 검증을 완료로 쓰지 않는다.
- 캐시 일관성은 같은 대상 시점·정보 기준일·증거 버전에서 정의한다. 현재 재검증은 새 근거와 정정을 반영한다.
- 사람 검수와 학습 권리 적격성을 분리한다. 3분류 결과를 6등급으로 단순 치환하지 않는다.

## 버전표기 규칙
1.0.0: 초기 릴리스

- x.x.n : 버그 수정 및 작은 개선
- x.n.0 : 새로운 기능 추가 (하위 호환성 유지)
- n.0.0 : 주요 업데이트 (하위 호환성 깨짐 가능)

위의 규칙에 따라서 수정시에 꼭 반영시키도록해줘  

### 시작 버전 (2026-07-07 교수님 지시)
- 백엔드(`package.json` + `src/config.js` `version`): **0.8.0**
- 프론트(`frontend/package.json`): **0.1.0**

### 버전 올리는 규칙 (워크플로우)
- **특별 지시 없으면**: 매 작업/커밋마다 **마지막 자리(patch, x.x.N)를 +1**.
- **교수님 지시가 있을 때**: 그다음 자리(minor/major) 상승 여부를 판단.
- **중요**: 교수님이 지시해도 **무조건 따르지 말고, 타당성을 먼저 피드백**한 뒤 진행할 것. (버전뿐 아니라 전반적 작업에 적용되는 원칙)
- 백엔드·프론트는 **독립적으로** 버전 관리(각자 변경 시 각자 +1).
- 이번 커밋에는 이미 완료한 기능 작업의 버전 상승(BE 0.8.1 → 0.8.6, FE 0.1.2 → 0.1.5)이 포함된다. 11월 18일 문서 정리는 그 미커밋 작업을 검증·기록하는 절차이며, 런타임 변경이나 추가 버전 상승·재배포를 하지 않는다.

## 보안 백로그

> 2026-07-06 결정: 지금은 파일럿이라 성능에 집중. 아래 보안 항목은 기록만 하고 나중에 처리.

- **DNS rebinding 하드닝**: `urlFetch.js`의 SSRF 방어는 현재 검증-후-fetch 사이에 미세한 재해석 창이 있음. 정적 벡터(메타데이터·사설·루프백·scheme·port·리다이렉트·IPv6 우회)는 전부 차단하지만, 완전 차단은 검증한 IP로 직접 연결하는 pinned-IP dispatcher 필요. (정부 보안심사 대비 실서비스 전 필수)
- 크롤러 응답 저장 시 개인정보/저작권 취급 정책 (RFP COR-003 저작권, SER-002 개인정보).
- API 키·비밀 관리 하드닝 (RFP SER-003) — 현재 `.env` 평문.
- robots.txt / 크롤링 rate limit / ToS 준수.
- 시큐어코딩 전면 점검 + 웹취약점(OWASP Top 10) 스캔 (RFP SER-001/005) — 실서비스 전.

- 2026-11-15 주 에이전트의 `npm audit` 확인: 기존 Express 하위 의존성(body-parser, path-to-regexp, proxy-addr, qs) 관련 5개 이슈가 남아 있다. 신규 Readability/jsdom 의존성에서 추가된 항목으로 분류하지 않았으며 기존 보안 백로그로 유지한다. 이는 11월 15일 당시 관측이며 11월 18일 새 취약점 스캔 결과가 아니다.
