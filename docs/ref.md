## Part 2. [붙임] 사업계획 요약서 — 작성 내용

> ※ 추진하고자 하는 AI 과제의 사업계획을 1매 내외로 작성

### 추진배경 및 필요성

- 인터넷 환경에서 **허위조작정보**로 인해 사회 혼란이 가중되어 신뢰도 향상 필요성이 강조됨
- 과거 **팩트체크넷**이 개발·운영된 바 있으나, 현 AI 시대를 대응하지 못하고 **운영중지 상태**임
- 최근 AI 기반 기술을 활용한 허위조작정보가 더욱 정교하게 만들어져 이에 상응하는 **대응 체계 구축**이 요구됨
- 팩트체크 플랫폼 구축에 소요되는 **예산 및 과업 내용의 적정성을 분석**하고, 이를 바탕으로 효과적인 팩트체크 플랫폼 구축이 필요함
- 대국민의 **신청·접수 기반 팩트체크 절차**를 마련하고, 전문가와 국민의 **집단지성**을 이용해 허위정보를 근절하는 토론의 공간에서 AI를 활용해 팩트체크할 수 있는 장치로 활용

### AI 서비스 구현 방안

> 적용 AI 기술(자연어처리, 영상인식, 예측모델 등), 서비스 구조, 활용 데이터, 기대 산출물 등

**전체 구조**: 본 시스템은 **상용 LLM(Teacher) → 검증 데이터 자산화 → 도메인 특화 sLLM(Student)** 으로 이어지는 **지식 증류(knowledge distillation) 기반 단계적 자립화** 구조로 설계한다. 초기에는 상용 생성형 AI를 활용해 빠르게 서비스를 운영하면서, 전문가·국민 집단지성으로 검증된 결과를 자체 학습 자산으로 축적하고, 이를 국산 베이스 모델 위에 LoRA·RAG·에이전트 하네스로 결합하여 **독자적인 진실 추론 시스템**을 구축한다.

<a id="teacher-processing"></a>

#### ① 상용 생성형 AI 기반 팩트체크 전처리 (Teacher 운영)

- **OpenAI / Anthropic / HyperCLOVA X** 등 상용 LLM을 활용해 입력 텍스트를 정규화하고, **사실 주장(claim) 단위로 분해**한다.
- 의견·주관 표현은 검증 대상에서 분리하고, 검증 가능한 사실 주장만 후속 단계로 전달한다.
- **데이터 주권 옵션** 명시: 국내 리전 / 온프레미스 / 범정부 AI 공통기반 GPU 활용을 단계별로 적용한다.

<a id="agent-orchestration"></a>

#### ② 다중 에이전트 오케스트레이션 (역할 분리형 추론 파이프라인)

- 단일 LLM 호출이 아니라 **역할별 추론 모듈(에이전트)** 을 분리하여 연결한다.
  - `Intake` (입력 정규화) / `Claim` (주장 추출) / `Source` (출처 추적) / `Fact` (근거 대조) / `Narrative` (편향·선동성 분석) / `Report` (리포트 생성)
- 각 에이전트는 **신뢰 출처 기반 근거 검색(RAG)** 과 외부 웹 검색을 호출하여 LLM의 사전지식이 아닌 **실제 외부 근거**로 판정한다.
- **공신력 5계층** 적용: `T0 원문·1차 자료` / `T1 초국가·공적 기관` / `T2 학술·전문 검증기관` / `T3 일반 언론` / `T4 SNS·커뮤니티`. 출처별 가중치를 다르게 둔다.

<a id="verification-loop"></a>

#### ③ 다중 검증 루프 (반복 팩트체크 + 보류 게이트)

- 동일 주장에 대해 **외부 근거를 재인출**하며 반복 검증한다.
- 종료 조건: 상위 계층(T0/T1) 근거가 충분히 모이거나, 임계 횟수 도달.
- **상위 계층 근거가 없거나 충돌하면 강제로 `보류(hold)`** 판정 — 억지 참/거짓 판정 방지.
- 동일 원문을 여러 매체가 재인용한 경우는 **독립 출처 1건**으로 카운트해 다수 노출의 환상을 차단한다.

<a id="verified-data"></a>

#### ④ 검증 데이터 자산화 (집단지성 검증 통과분의 학습 풀 구축)

- Teacher의 출력은 즉시 학습 데이터로 쓰지 않는다. **반드시 인간 검증을 거친 결과만** 학습 풀에 진입시킨다.
  - 1차: **전문가 자문단** 라벨링 / 2차: **국민 집단지성** 검증 / 3차: 평가자 간 일치도(IAA) 측정
- 이 절차는 오류가 학습 데이터에 재유입되는 위험을 줄이려는 품질 관리 구상이다. 인간 검수만으로 제공사 계약·원자료 이용권·학습 목적별 적격성이나 공공사업 요건 충족이 보장되지는 않으며 각각 확인해야 한다.
- 산출물: **한국어 팩트체크 골드 데이터셋**, **신뢰 출처 메타데이터 레지스트리**.

<a id="student-system"></a>

#### ⑤ 독자적 진실 추론 시스템 (도메인 특화 sLLM + RAG + 에이전트 하네스)

- **국산 베이스 모델**(EXAONE / SOLAR / Kanana / A.X 등 후보) 위에 ④의 검증 데이터셋으로 **경량 도메인 적응 학습(LoRA / QLoRA)** 을 적용한다.
- 모델 가중치만으로 자립하는 것이 아니라, **RAG(자체 신뢰 DB) + 에이전트 오케스트레이션 + 검증 하네스**가 결합된 **복합 AI 시스템(compound AI system)** 형태로 구축한다.
- "독자성"은 베이스 모델의 처음부터 학습이 아니라 **한국어 도메인 데이터 + 국내 신뢰 출처 DB + 자체 평가·운영 하네스**에서 확보한다.
- 최신 사실 갱신은 **재학습 없이 RAG 신뢰 DB만 갱신**하여 대응 — 팩트체크 시스템의 핵심 요건인 **최신성 유지**를 비용 효율적으로 달성한다.

#### 적용 AI 기술 요약

- 자연어처리(NLP): claim 추출, 의견·사실 분류, 편향 탐지
- 정보 검색(RAG): 신뢰 출처 기반 근거 인출
- 멀티모달(확장): 이미지·영상 조작 탐지(딥페이크) — 2단계 확장 항목
- 경량 미세조정(LoRA/QLoRA): 도메인 특화 적응
- 에이전트 오케스트레이션: 역할 분리형 추론 파이프라인

#### 활용 데이터

- 공공·국제기관의 1차 자료(통계청, 국제기구 발표 등)
- 학술·전문 검증기관 자료
- 검증 통과분 누적 골드 데이터셋
- 사용자 신청·접수 기반 실시간 질의 로그(개인정보 비식별화 후)

#### 기대 산출물

- 대국민 실시간 팩트체크 서비스 (웹/모바일)
- 한국어 팩트체크 도메인 특화 sLLM (LoRA 가중치 + RAG 인덱스)
- 신뢰 출처 메타데이터 레지스트리
- 다층 검증 리포트 표준 스키마 (사실·출처·이해관계·서사·확산 분리)

### 차별화 포인트

- **과거 팩트체크넷의 운영중지** 사례를 명시적으로 언급 → AI 시대 대응 실패가 핵심 원인
- Marbas의 강점:
  - **단계적 자립화 구조**: Teacher → 검증 데이터 → Student로 이어지는 증류 기반 자립화 (예산 현실성 + 데이터 주권 동시 달성)
  - 실시간 질의 (요청 시점 검색·수집)
  - 다층 검증 리포트 (사실 판정 + 출처 무결성 + 이해관계 + 서사 압력 + 집단 확산 리스크 + 가설성 인과)
  - 공신력 5계층 (T0 1차자료 ~ T4 SNS) 기반 게이트 판정
  - 집단지성과 AI의 결합 (수요조사서의 "전문가·국민 집단지성" 키워드와 정합)
  - **국산 베이스 모델 + 자체 RAG**로 독자성 확보 — from-scratch 사전학습 회피로 비용 효율
  - **재학습 없는 최신성 유지**: RAG 신뢰 DB 갱신만으로 새로운 사실 대응

### 거버넌스·법적 안전장치

- **학습 권리 별도 확인**: 인간 검수는 품질 관문이다. 제공사 계약·원자료 권리·학습 목적별 적격성까지 확인한 자료만 학습 대상으로 승인한다.
- **Model collapse 방지**: 자기 출력 학습 루프 차단을 위한 IAA(평가자 간 일치도) 검증
- **거짓 판정 거버넌스**: 정정 절차, 명예훼손·검열 시비 대응 프로세스
- **억지 판정 방지**: `보류(hold)` 비율을 KPI에 포함 — "모르는 것은 모른다" 원칙
