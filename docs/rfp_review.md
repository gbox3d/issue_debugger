| 항목 | 내용 |
|---|---|
| 발주기관 | 시청자미디어재단 (기존 팩트체크넷 운영주체 이관) |
| 사업명 | 팩트체크플랫폼 고도화 |
| 예산 | 2억 2천만원 (부가세 포함) |

| 참가자격 | **소기업만 가능**(대기업·중견기업 배제), **공동수급(컨소시엄) 불가** |

## 2. 사업 범위 (몸통)

사업의 핵심은 AI가 아니라 **전통적인 정부 SI(전자정부프레임워크 기반 플랫폼 재구축)**이며, AI는 그 안의 파일럿 모듈 하나다.

- 기존 팩트체크넷(AWS) 분석 후 신규 클라우드로 DB 이관
- UI/UX 전면 개편 (반응형, 웹표준·접근성)
- 역할별 기능: 일반사용자 / 전문팩트체커 / 재단관리자
- 6등급 판정 체계 + 검증 리포트
- 자료실·소개·공지 등 콘텐츠 통합 관리(CMS)
- 지정 개발 스택: **JSP + 전자정부표준프레임워크 + MariaDB + Apache/Tomcat**

## 3. AI 관련 요구사항 (파일럿 범위)

| 요구사항 | 내용 |
|---|---|
| SFR-009 | 텍스트 입력 → LLM API 연동 주장 자동추출, 웹검색 연동, 팩트체커 보조 |
| SFR-010 | 웹검색 기반 검증 보조 파일럿 — **자동판정 아님**, 보조 도구로 한정 |
| PER-004 | 주장추출 10초 이내 응답 |
| SER-003 | LLM API 키 환경변수/비밀관리, 하드코딩 금지 |
| SIR-003 | 외부 LLM·웹검색 연동 + 오픈 API 설계·문서화 |
| 비용 | 2개 이상 생성형 AI 모델의 토큰비용은 **사업자 부담** |
| 2단계 예고 | 이벤트 페이지 등은 "2단계 사업 반영 예정"으로 명시적 유보 |

## 4. Marbas 로드맵과의 정합성

| 구분 | 내용 |
|---|---|
| 일치 | `plan.md` Phase 1(Teacher/OpenAI adapter), Phase 4(URL 수집), LLM Adapter 인터페이스가 SFR-009/SIR-003/SER-003과 거의 그대로 겹침 |
| 스택 불일치 | Marbas = Node/Express + React, RFP = JSP/전자정부프레임워크/MariaDB → Marbas는 플랫폼 전체가 아니라 신규 시스템이 호출하는 **외부 AI API 모듈**로 포지셔닝하는 편이 현실적 |
| 범위 온도차 | RFP는 "파일럿"으로 명시적으로 한정, `plan.md` Phase 5~12(다층 신뢰계층, 게이트 판정, Student sLLM 자립화)는 훨씬 장기적인 비전 → 이번 입찰에는 "향후 로드맵"으로만 제시하는 수준이 적절 |

## 5. 열린 질문 (미결)

1. 입찰 참여 형태 — 직접 주사업자(소기업 자격 + JSP/전자정부프레임워크 개발력 필요) vs 주사업자에게 AI 서브모듈로 공급
2. 참여 시 Phase 1~4 최우선 마감 필요 (선정 '26.8, 일정 빠듯함)
3. 판정 체계 재매핑 — 현재 `true/false/hold/mixed` → RFP 6등급(사실/대체로사실/절반의사실/대체로사실아님/사실아님/판단불가)
4. `/api/verify`를 SIR-003 요구에 맞춰 오픈 API 스펙으로 문서화
