## 범위와 확정 규칙

사용자의 “여기까지 작업 커밋·문서 정리·독립 에이전트 3명 다수결 확정” 요청에 따른 문서 심사다. 이미 완료한 BE 0.8.6 / FE 0.1.5 개발 작업과 이번 문서 정리를 함께 커밋 대상으로 삼는다. 구현 전체를 새로 개발하거나 11월 15일 심사 점수를 다시 부여하는 작업은 아니다.

주 에이전트가 문서를 정리하고, 서로 분리된 컨텍스트의 평가자 3명이 같은 후보와 실제 코드·검증 자료를 읽는다. 다른 평가자의 의견·점수·투표는 최종 투표 전에 공유하지 않는다. 각자는 10점 척도의 평가와 **찬성/반대** 및 근거를 내며, **3명 중 2명 이상 찬성**이면 문서를 확정한다. 문서 점수는 사실 정확도 백분율이 아니며, 과거 개발 심사의 8점/7점 기준·반복 횟수와 별개다. 같은 계열 모델이므로 공통 오류 가능성은 남는다.

검토 대상을 [후보 파일·SHA-256 목록](./validation/20261118/candidate-manifest.json)으로 고정한다. 파일별 내용 해시와 `sha256 + 두 공백 + 상대 경로 + LF`를 경로순으로 합친 목록의 SHA-256을 사용한다. 심사 중 검토 대상이 바뀌면 새 후보를 만들어 다시 투표한다. 후보 목록 자체, 이 결과 대장, [투표 JSON](./validation/20261118/votes.json)은 자기 참조와 투표 후 기록을 위해 내용 해시 대상에서 제외한다. 이 세 파일에는 후보 식별·실제 수신 표·결정만 추가하며, 승인받은 구현·설명 문서를 수정하는 우회로 사용하지 않는다.

- KMA 종료 재임 실험 → 첫 중단 → 일반 원문 검증 → 자동 검색 실패·두 번째 중단 → 새 목표의 1차 미통과·같은 2차 최종 8.4 통과를 구분했다. 실패·중단 기록을 삭제하지 않았다.
- 4월 설계, 7월 사업·GPU 구상은 과거 제안으로 명시하고, 계획 API·Student·인간 검수·다중모델 합의를 구현 완료로 읽지 않도록 했다. 출처 미확인 성능·가격 수치는 현재 성능·시세가 아니다.
- Naver 관련도순, 서버 내부 검색 도구, 핵심 3개 주장, 수집 예산, 부분 본문·날짜·반증 보류, 선택 A/C와 필수 B/D, 저장·재생·검토 캐시·토큰 계측을 실제 코드와 대조했다.
- 로컬 프론트 API 설정과 운영 `/marbas` 설정을 구분했다. 저장 자료의 범위, TTL과 삭제의 차이, UUID 조회와 인증 부재를 명시했다. 과거 감사 기록의 ID도 익명 자료가 아니다.
- 사람 검수와 데이터 학습 권리를 분리하고, 끊긴 로컬 문서·목차 링크를 정리했다. 특허 원문은 로컬 참고 자료이며 신규성·법적 유효성을 이번 작업에서 확정하지 않았다.

## 검증 근거

[11월 18일 재검증 JSON](./validation/20261118/verification.json)에 환경·명령·결과·로그 해시를 기록한다. Node 24.22.3 / npm 11.19.1에서 **128/128 테스트 통과**, 프론트엔드 임시 경로 빌드 성공을 확인했다. 테스트는 모의 응답을 포함한 로컬 회귀 검사이며 외부 모델 정확도 평가가 아니다.

11월 15일의 실제 운영 접속·유료 모델·기사 입력·모바일 검증과 고정 원문 캐시 측정은 [기존 목표 기록](./article_search_goal_20261115.md) 및 당시 감사 JSON에 남긴다. 이번에는 새 운영 접속·배포·모델 호출로 재검증했다고 주장하지 않는다. 빌드 결과는 `/tmp/marbas-commit-build-20261118`에만 생성했다.
