## 작업 범위와 현재 상태

> 이 문서는 2026-11-15의 제한 파일럿부터 두 번째 중단까지의 이력이다. 같은 날 후속 [새 자동 기사 검색 목표](./article_search_goal_20261115.md)는 정식 1차 6.8 미통과 후 같은 2차에서 후보 8.3 → 운영 확인 후 최종 8.4/10으로 종료됐다. 아래 중단·재개 규칙과 “현재”는 당시 단계에만 적용된다. 현재 계약과 전체 순서는 [문서 안내](./README.md)를 따른다.

- 기준일: 2026-11-15 (Asia/Seoul).
- 사용자는 검토 결과와 첫 개발 범위에서 실용적인 기능 구현, 에이전트별 담당, 독립 검토 점수 기준, 기록관 운영을 요청했다.
- 원래 목표: **시간에 따라 변하는 일반 사실을 검증하는 AI 에이전트**. 사용자는 기상청이나 인사 전용 제품으로의 전환을 요청하지 않았다.
- 두 번째 중단 당시 상태: **실사용 자동 검색 실패로 공식 적합성 재평가 5.5/10, 개발 중단 누적 2회**. 당시에는 읽기 전용 교정 설계 중이었고 새 코드 수정 전이었다. 적합성 재심사 7/10 이상 후 재개하며 중단 3회 누적 시 작업을 중지한다. 이전 품질 8.0/10·적합성 8.2/10과 배포는 이력으로 보존하되 자동 기사 검색 실용성을 입증한 것으로 확대하지 않는다.
- 범위 정정: 기상청 전용 파일럿을 원래 제품 목표의 완료로 취급한 것은 주 에이전트의 범위 판단 오류였다. 일반 경로의 시간 의존 주장을 모두 보류하던 기존 구현은 원래 목표를 충족하지 못했으며 이를 교정한다.
- 기존 평가의 의미: **8.4/10은 제한 파일럿 내부 품질 평가이며 정확도 84%가 아니다**. 기상청 공식 이력은 해당 재임 사례의 정답 대조 근거일 뿐, 시스템 전체 정확도·판정 가능 비율(coverage)의 평가 근거가 아니다. 기존 구현·테스트·배포 이력은 아래에 보존한다.
- 두 번째 중단 이전 교정 구현 버전: backend **0.8.5**, frontend **0.1.4**. 마지막 수정 후 실제 API 재검증과 최종 품질 심사를 통과했다. PM2 재시작·프로덕션 빌드와 운영 화면의 실제 제출·저장·재생 검증도 통과했다. 이전 배포 버전은 backend 0.8.4 / frontend 0.1.3이다.
- 이전 제한 실험 대상: [기상청 공식 역대 청장 이력](https://www.kma.go.kr/kma/org/chief/generation_01.jsp)의 종료된 재임기간을 이용한 특정 인물·특정 날짜의 재직 상태 검증. 고정된 공식 URL만 사용한다.
- 기존 구현의 판정 범위: 모르는 이름·공백 기간·진행 중 임기·겹친 기간은 보류한다. `false`에는 다른 알려진 청장의 종료된 재임기간이라는 반증이 필요하다.
- 구현 API: `POST /api/personnel/verify`, `GET /api/personnel/reports/:id`. 개별 UUID 보고서로 판정·근거를 보존한다.
- 구현 흐름: 입력 구조화 → 공식 원문 확인 → 원문 행·내용 해시·수집 시각·근거 ID → 시간 적합성 및 판정 게이트 → 보류 사유/근거/판정 이력 표시.
- 모드: `retrospective`는 요청 때 새로 수집한 공식 자료로 과거를 재검증한다. `as_known`은 정보 기준일 이전에 실제 수집·저장한 적격 스냅샷을 사용하며, 없으면 당시 판단 재현 불가로 보류한다. 현재 문서의 오래된 날짜를 당시 문서 상태로 간주하지 않는다.
- 자연어는 단일 긍정형 기상청 청장 재직 주장만 지원한다. Claude가 인물·기관·직위를 구조화하며 원문 행과 날짜 판정은 코드에서 검사한다. 구조화 `person` 입력도 지원한다.
- 재검증은 같은 요청의 `previous_id`를 연결한 새 UUID 보고서를 생성하고 이전 보고서를 덮어쓰지 않는다. 전체 보고서 목록 API는 제공하지 않으며 브라우저에는 보고서 ID만 저장한다.
- 이전 일반 `/api/verify`에는 수집 근거 ID·인용 일치 검사, 무근거·의견·상충 보류가 있었으나 시간 의존 주장을 일괄 보류했다. 이 제약을 교정 구현에서 원문·시점·별도 검토 조건에 따른 판정으로 변경했다. 사실 confidence는 표현 점수와 분리하며 모델 자체 점수다.
- 범위 밖: 모든 기관의 현재 재직 상태 보증, 전체 한국어 팩트체크 정확도 주장, 200~300개 인간 골드셋 구축 완료, 자체 GPU 구매·Student 학습, 특허 전체 다중모델 토론 구현 완료.

## 실사용 자동 검색 실패와 2차 중단

- 재현 보고서 ID: `1c48a416-de43-4a77-b416-98dd0a2e8b50`. 사용자가 키워드 기반 검증에서 원문 0개로 끝난 결과를 보고했다. 주 에이전트는 별도 웹검색에서 관련 보도를 확인했다. 개인명·주장 세부는 문서에 복제하지 않는다.
- 확인한 기술 원인: Tavily 6개와 Naver 6개를 순서대로 합친 뒤 앞 6개만 택해 Naver 후보가 제외될 수 있었다. 실제로 선택된 YouTube 1개와 수집 실패 5개 뒤의 후보로 넘어가지 않았다. 긴 한영 혼합 검색어 하나에 의존했고 검색 장애·결과 없음·원문 수집 실패를 충분히 구분하지 않았다. 이는 주 에이전트 조사 결과이며 이후 교정 검증으로 재확인한다.
- 이전 검증의 공백: 기록관이 `/tmp/marbas-general-api-final-20261115.json`의 6개 요청과 운영 Chrome 산출물을 확인했다. 모두 텍스트가 있고 입력 `url`은 없으며 **명시적 `source_urls` 1개**가 제공됐다. 6/6은 지정 원문에서 시점 판정·저장까지의 결과이며 `source_urls` 없는 자동 기사 검색이나 기사 URL 단독 입력의 실제 성공 증거가 아니다. 67개 자동 테스트도 이 실사용 공백을 해소하지 못했다.
- 당시 공식 조치: `quality_gate` 적합성 **5.5/10**, 중단 누적 **2회**. 당시에는 코드 수정 없이 읽기 전용 교정 설계 중이었으며 재개 점수나 새 검증 결과를 받기 전이었다. 재심사 7/10 이상 후 재개·누적 3회 중지 규칙이 적용됐다. 이후 사용자가 새 목표와 반복 규칙을 지정한 경과는 위 후속 기록을 따른다.
- 다음 검증에서 구분할 입력 경로는 키워드만 입력, 기사 URL 단독 입력, 명시적 근거 URL 제공이다. 검색 결과 부재·검색 오류·수집 실패를 구분하고, 여러 후보가 존재해도 사용 가능한 원문이 확보되지 않는 경로를 재현해야 한다. 교정 구현 범위·통과 기준은 재심사에서 확정한다.

## 교정안 재검토와 구현 재개

> 아래는 **첫 중단 이후, 두 번째 중단 이전**의 BE 0.8.5 / FE 0.1.4 기록이다. 6개 URL 한도·67개 테스트·명시 원문 중심 검증을 현재 자동 검색 기능 전체의 근거로 확대하지 않는다.

- 작업 상태 질문에 미완료·개발 중단 상태를 설명한 후 읽기 전용 설계 검토를 진행했다. `quality_gate`의 재개 적합성 **8.0/10**을 수신하여 구현을 재개했다. 중단 누적은 **1회**이며 이 점수는 설계의 재개 판단이다. 최종 구현 품질이나 정확도 평가 결과가 아니다.
- 채택한 첫 범위: 특정 기관에 고정되지 않은 일반 주장에 대해 명시적 시점 근거를 사용한 판정 MVP를 구현한다. 일반 원문 수집·스냅샷·대상 시점과 정보 기준 분리·보고서 저장, 일반 입력 중심 화면·근거·판정 이력을 포함한다. 근거 부족·상충·과거 자료 부재의 보류 조건을 유지하고 기상청 기능은 보조 예제로 둔다. 모든 기관·모든 주장의 정확성을 보증하지 않는다.
- 확인한 구현: 사실 대조 B와 별도 문맥의 독립 검토 D, 원문·시간 인용 검사를 통합했다. 같은 모델을 사용하므로 공통 오류 가능성이 남는다. 일반 API·시간·저장 계약은 `src/services/verification/{service,time,store}.js`와 `src/routes/verify.js`를 확인하고 `readme.md`에 반영했다.
- 효용 검증: 아래 3분야 사례로 날짜 전후의 판정과 보류 사유를 확인했다. 사례별 정답 근거와 기능 검증을 전체 정확도·coverage 평가와 구분한다. 인간 정답셋에 의한 폭넓은 평가와 장기 확장은 이번 완료 범위에 포함하지 않는다.
- 향후 확장과 구분: 전체 분야 정확도 평가용 인간 골드셋, 대규모 수집·과거 아카이브, 전체 인간 검수·정정 운영, 특허의 다중모델 토론, Student/GPU 투자를 이번 첫 범위의 완료로 주장하지 않는다. 기존 기상청 구현은 제한 실험 이력으로 보존한다.
- 일반 API: `POST /api/verify`는 `text` 또는 `url`, 선택 `source_urls`(최대 3개), `subject_date`, `mode`, `knowledge_cutoff`, `previous_id`를 받는다. `GET /api/reports/:id`는 저장 결과를 재생하며 동일 정규화 요청의 재검증은 새 UUID와 이전 ID를 연결한다. `as_known`은 기준 시각 이전에 실제 저장한 원문만 사용하고 새 웹검색·원문 수집을 하지 않는다.
- 저장·수집: `GENERAL_DATA_DIR` 기본값은 `./data/verification`이며 추출 본문 스냅샷과 보고서를 원자적으로 저장한다. 일반 수집은 Readability 기사 본문을 우선 추출하고 `extraction_scope`를 기록한다. 스크립트는 실행하지 않는다. 요청당 6개 URL·자료별 모델 전달 12,000자 한도가 있으며 잘린 자료로 확정하지 않는다.
- 중간 검토: 적합성 **7.5/10**, 중단 누적 **1회** 유지. 중복 인용에서 시간 검사 누락 및 모듈 단위의 미래 스냅샷 문맥 허용 지적을 수정하고 회귀 검사 3개를 추가했다.
- 추가 검토 반영: 서버가 추출 주장의 `original_quote`가 실제 입력에 포함되는지 검사하고 B/D의 `claim_preserved=true`를 요구한다. 완전한 자료는 `sources`로 확정 근거 검토에, 잘린 자료는 `context_only_sources`로 정정·반증·문맥 검토에 전달한다. 부분 본문을 통째로 제외해 알려진 반증을 숨기는 문제를 수정했으며 부분 본문 확정 인용은 금지하고 미해결 반증은 보류한다.
- 실제 검증 경과: 첫 판정 모듈 스모크 **1/6** → 첫 전체 API **3/6** → 수정 후 전체 API **6/6**이 예상 판정과 일치했다. confidence의 0~100 출력·메뉴의 본문 한도 소모를 확인해 임계값 완화 없이 0~1 스키마 명시·기사 본문 추출로 수정했다. 6건은 Python 3.12 출시·Voyager 1 발사·핀란드 NATO 가입의 날짜 전후 사례이며 전체 정확도 평가가 아니다. 마지막 부분 본문 문맥 보완 후 같은 6건을 다시 실행해 **6/6 통과**했다.

## 개발 역할

- 주 에이전트: 범위·통합·변경 조정 및 중단 규칙 집행.
- `general_backend`: 교정 구현의 일반 원문 수집·스냅샷·시점 분리·보고서 저장.
- `personnel_ui`: 교정 구현의 일반 입력 중심 UI·시점·근거·판정 이력.
- 주 에이전트: 사실 대조 B와 독립 검토 D, 원문·시간 인용 판정 게이트 및 통합 검증.
- 이전 `personnel_backend`의 공식 재임 자료 파싱·저장·테스트는 제한 실험 이력으로 보존한다.
- `quality_gate`: 구현과 독립된 설계 적합성·최종 품질 평가. 점수와 근거를 보고한다.
- `archivist`: 문서의 부정확한 단정 정정, 의사결정·심사·검증 결과 기록. 소스 코드와 비밀 설정은 수정하지 않는다.

## 적합성·품질 통과 규칙

이 절은 새 목표 이전 단계의 규칙이다. 11월 15일 후속 목표는 작업물 >8점·목표 >7점 규칙, 11월 18일 문서 확정은 독립 3명 중 2명 이상 찬성 규칙으로 구분한다.

1. 최종 품질은 **10점 만점 중 7점 이상**일 때만 통과한다.
2. 단계별 작업 적합성이 **6점 이하**이면 즉시 개발을 중단한다.
3. 중단 사유와 수정 방향을 재검토하고 **7점 이상**으로 확인된 뒤 재개한다.
4. 이 적합성 중단이 **3회 누적**되면 작업을 중지하고 사용자에게 상태를 보고한다. 점수를 임의로 조정해 우회하지 않는다.
5. 점수, 평가자, 근거, 중단 횟수, 재개 사유를 함께 기록한다. 점수 미수신 상태를 통과로 취급하지 않는다.

## 문서 재검토 반영

- Du et al. 연구는 동일 모델 실험 외에 ChatGPT·Bard 교차 모델 실험도 포함한다. 모델 다양성만을 차이로 단정한 비교를 정정했다. [원논문 §3.3](https://arxiv.org/html/2305.14325v1#S3.SS3)
- 캐싱의 일관성은 같은 시점·근거·모델·규칙 버전 조건으로 한정하고, 새 근거·정정 이후 최신 판정을 재검증한다.
- 3분류→6등급 단순 치환 방침을 별도 정의·라벨링·검수·평가 필요로 수정했다.
- 자체 GPU가 재현성·평가·자산화의 선행 필수조건이라는 단정과 평가 비용이 공짜라는 표현을 수정했다. 구매 규모는 실제 부하·품질·총비용으로 판단한다.
- 인간 검수는 품질 관리이며 제공사 계약·원자료 권리·학습 목적별 적격성을 자동 확보하지 않는다. [Anthropic 상용 약관](https://www.anthropic.com/legal/commercial-terms)
- 특허 원문은 로컬 참고 자료이며 Git 배포 문서에 포함하지 않는다. 당시 Markdown 협업 검토 메모를 수정했으며 특허 신규성·유효성을 확정하지 않는다.

## 검증 결과와 한계

- 아래 결과는 중단 이전 제한 실험의 이력이다. 원래 목표의 완료나 일반 사실 검증 정확도를 입증하지 않는다. 중단 유지 기간에는 문서 정정만 수행했으며, 이후 적합성 8.0/10으로 재개한 교정 구현의 진행 결과는 위 별도 절에 기록한다. 교정 구현의 품질 심사와 운영 화면 검증도 통과했으며 위 별도 절에 기록했다.
- 개발 전 조사: 기존 테스트 10개는 통과했지만 설정·Anthropic 어댑터 계약 검증 중심이었다.
- 개발 전 합성 응답 재현: 근거 없는 `supported/confidence=0.99`와 의견형 주장도 최종 `true`가 되는 경로가 확인됐다. 이는 모델의 실제 오류 발생률 측정이 아닌 코드 방어 결함의 재현이다.
- 주 에이전트 검증: `npm test` **35개 통과**, `git diff --check` 통과, 프론트엔드 `npm run build` 성공.
- 검토 에이전트의 별도 **9개 프로브 통과**: 재임명·경계일·공백, 7건 동시 저장, 스냅샷 기준일 조건 등을 점검했다. 이는 35개 테스트와 구분한 추가 점검이다.
- 실제 공식 원문을 사용한 확인: 김종석 / 2019-06-01 → `true`; 김종석 / 2021-01-01 → 다른 청장 재임기간을 반증으로 `false`; 2019년 정보 기준일의 `as_known` → 당시 저장 스냅샷 부재로 `hold`.
- 실제 Claude Opus 자연어 호출: 단일 문장 검증이 HTTP 200·`true`로 완료됐다. 약 3.06초는 해당 단일 스모크 관측이며 평균·p95 또는 성능 보장 수치가 아니다.
- 실제 Chrome 점검: 세 판정 경로, 이전 보고서 GET, 새 UUID와 `previous_id`가 연결된 재검증, 390px 모바일 가로 넘침 없음, 페이지 오류 0건, 브라우저에 보고서 ID만 저장함을 확인했다.
- 영속 저장: `src/services/personnel/store.js`가 실제 수집 본문·SHA-256·수집시각과 UUID 보고서를 로컬 저장소에 원자적으로 기록한다. `PERSONNEL_DATA_DIR`로 저장 위치를 지정할 수 있다.
- 운영 반영: 프론트 빌드 후 PM2 `marbas-api`를 재시작하고 backend `0.8.4`를 확인했다. 로컬 3001 포트의 신규 검증 API가 HTTP 200·`true`로 보고서를 저장했으며 GET 조회와 일치했다. [기존 운영 화면](http://bsqai01.iptime.org:21080/marbas/)과 `/marbas/version`이 HTTP 200으로 응답했다. 실제 Chrome이 운영 URL에 직접 접속해 설정 가로채기 없이 재임 여부 확인 → `true`, 화면 BE `0.8.4` / FE `0.1.3`을 확인했다. 검증용 임시 미리보기 서버 2개는 종료했다.
