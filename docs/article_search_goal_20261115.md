## 현재 목표와 규칙

- 상태: **새 목표 달성 및 운영 검증 완료**. 독립 `delivery_review`의 같은 정식 **2차 최종 심사 8.4/10 통과**, 사용한 심사는 **2/3**이며 3차는 사용하지 않았다. 1차 6.8 미통과와 2차 배포 전 후보 8.3은 이력으로 보존한다. 운영 BE **0.8.6** / FE **0.1.5**, `general-news-v3`를 실제 키워드·기사 URL 단독·보고서 재생으로 검증했다. 평가 점수는 정확도 백분율이 아니다.
- 목표: 오타가 포함된 사용자 키워드에서 관련 뉴스를 자동 확보하고, 주장·발언·외부 보도를 구분해 근거와 시점에 맞는 답을 제공한다. 기사 URL 단독 입력과 자원 효율도 검증한다.
- 이전 적합성 중단 **2회**와 실패·성과는 [이전 구현 기록](./implementation_review_20261115.md)에 보존한다. 최신 지시가 이전 중단·재개 절차를 대체하며 이번 목표의 반복 횟수는 별도로 시작한다.
- 일반 작업물은 개발 총괄 `root`의 검증 **8/10 초과**여야 통과하며, 개선 작업별 최대 **5회**다. 정확히 8점은 통과가 아니다.
- 목표 전체는 독립 `delivery_review` 심사 **7/10 초과**, 최대 **3회**다. 정확히 7점은 통과가 아니다.
- 자원 효율 3개 작업은 각각 **7/10 초과**를 요구한다. 각 최대 **5회** 개선 후에도 정체되면 해당 작업을 중단하고 사용자와 상의한다. 미수신 점수는 통과로 기록하지 않는다.

## 성공 조건

1. 오타 포함 키워드만 입력(`source_urls=[]`, 입력 `url` 없음)해 실제 관련 기사 원문을 자동 확보한다. 특정 사례용 URL 주입·정답 하드코딩으로 대체하지 않는다.
2. 본인이 말한 내용, 상대를 지목한 보도, 해당 주장 자체가 입증됐는지를 구분한다. 기사 존재만으로 의혹을 사실로 확정하지 않는다.
3. 실제 기사 URL만 입력한 경로를 검증하고, 입력 기사와 외부 교차 자료의 역할·출처를 분리해 보여준다.
4. 검색 장애, 검색 결과 0건, 원문 수집 실패, 검증 미실행을 구분한다. 후속 후보 수집과 근거 확보 결과를 실제 경로로 확인한다.
5. 반증·명제 보존·원문 인용·시점·보류 조건을 유지한다. 로컬 근거/결과 캐시와 중복 AI 호출 절감 전후의 호출 수·사용량·시간을 같은 조건에서 측정하고 회귀를 확인한다.
6. 실제 운영 UI/API에서 자동 검색·기사 단독·보고서 재생을 확인한다. 사례별 통과와 전체 정확도·coverage를 구분한다. 문서에는 개인명·추문 세부를 확산하지 않고 보고서 ID와 기술 현상만 기록한다.

## 역할과 진행 순서

| 담당 | 책임 |
|---|---|
| `root` | 개발 총괄, 작업물 검증, 통합·운영 확인, 개선 횟수 관리 |
| `article_retrieval` | 자동 뉴스 검색·후보 선택·원문 확보·검색/수집 진단 |
| `personnel_ui` | 일반 입력·기사 단독·근거 구분·실패 상태 UI |
| `delivery_review` | 정식 1차 6.8 미통과 → 같은 2차 후보 8.3·운영 확인 후 최종 8.4 통과. 2/3 사용 |
| 자원 효율 에이전트 1 | 근거/결과 캐시와 시점·근거 버전 무결성 |
| 자원 효율 에이전트 2 | 중복 AI 호출 절감과 검토 역할 보존 |
| 자원 효율 에이전트 3 | 사용량 계량·동일 조건 비교·회귀 검증 |
| `archivist` | 계획·점수·반복·검증 이력 기록, 코드 수정 없음 |

진행 순서: 검색 실패 재현·진단 → 뉴스/UI 개선과 효율 작업 → root 작업물 검증 및 필요한 개선 → 독립 목표 심사 → 운영 검증 및 결과 기록. 코드 검토 통과와 실제 입력·브라우저 검증, 정식 목표 통과를 구분한다.

## 구현·검증 결과

- 정식 1차 심사에서 보류 결과의 `temporal_note`가 상단 요약에 사실 확정처럼 노출되는 우회 문제로 **6.8/10 미통과**했다. root는 서버의 안전하지 않은 note/summary를 제거하고, UI에도 과거 보고서를 포함한 보류 대체 문구와 상세 서술 숨김을 적용했다. 회귀 검사 후 2차 배포 전 후보 심사 8.3/10을 받았다. 같은 2차에서 운영 검증 후 최종 8.4/10으로 목표 달성을 확인했다.
- 최신 root 검증: 뉴스 8.6, UI 8.5, 통합 8.5. 개선 횟수는 뉴스 3회(반증 검색 예산 확보, 대체 반증 질의·짧은 본문, 한영 관련성), UI 2회(구체 답변/사용량, 출처 역할/보류 요약 방어), 통합 3회(null 필드, 엄격한 근거/날짜, 1차 심사의 요약 우회)다.
- 자원 효율 최종 모듈 평가: 캐시 **8.4/10**, 실행 정책 **8.2/10**, 사용량 **8.5/10**. 캐시는 `dated_report` 호환과 강제 무효화로 2회 개선했다. 강제 갱신이 이전 통과 결과를 되살리지 않게 하며, 새 근거 확보 후 날짜·해시·규칙 등이 다르면 캐시가 빗나간다. B/D는 필수, A/C는 선택이고 제공사 실제 토큰을 요청별로 계량한다.
- 최신 자동 검사 **128/128 통과**: `/tmp/marbas-news-tests-gate2-20261115.log`. 초기 통합 110/111 실패와 null 수정 이력은 보존하며, 새 한영 별칭 관련성·요약 우회 회귀를 포함한다. 각 모듈의 이전 집중 검사 수를 전체 수에 다시 합산하지 않는다.
- 실제 URL 없는 키워드 보고서 `1c2663bd-9255-4ed5-81ad-2cc81ead3932`: 사용 가능한 원문 6개, AI 호출 3회, 유효 인용을 확인했다. 보도 내용에 대한 구체 답변과 실제 주장 판정을 구분하며, 반증 검색 미완료로 최종 판정은 hold다. 관련 개인명·주장 세부는 기록하지 않는다.
- 실제 기사 URL 단독 보고서 `c310d395-cac2-4c20-9549-7c098eaf045b`: 8개 주장 추출 중 핵심 3개 검토, 보도 근거 범위의 true 2개·hold 1개, AI 호출 7회. 나머지 5개는 미검증임을 표시한다. 전체 기사 사실을 검증했다고 표현하지 않는다.
- 브라우저: 데스크톱 1365px·모바일 390px에서 가로 넘침·JavaScript 오류 없음. 실제 입력·기사·브라우저 산출물은 `/tmp/marbas-news-final-20261115/{keyword,article,browser}.json`이다. 아래 별도 운영 검증에서도 실제 입력·재생과 화면을 확인했다.
- 내부 도구 `search_news`·`search_web`·`fetch_article`은 별도 MCP 설치가 필요하지 않은 애플리케이션 계약이다. 주 질의·반증·대체 질의로 후보를 확보하고, 기사 입력과 외부 교차 자료를 분리한다.

고정 원문 캐시 모듈 실측: 동일한 Python 공식 출시 페이지를 새로 가져와 같은 해시임을 확인한 비교다. **키워드 자동 검색 전체 경로의 성능 측정은 아니다.** 저장 보고서 GET 재생은 별도로 AI를 호출하지 않는다.

|---|---:|---:|---:|---:|
| 캐시 없음 | 2 | 8,508 | 2,481 | 14.139초 |

운영 반영: 공개 `/marbas/`에 BE 0.8.6 / FE 0.1.5를 배포하고 PM2 `marbas-api` online을 확인했다. 검토한 `/tmp` 프론트 빌드를 디렉터리 교체로 반영했고 이전 프론트는 `/tmp/marbas-frontend-before-0.8.6-20261115`에 보존했다.

- 운영 키워드 보고서 `7e4054f8-eab7-4d85-b31e-ee218625a2cf`: 명시 URL 없이 사용 가능한 원문 6개, AI 3호출, 유효한 보도 근거 답변. 반증 검색 미완료로 최종 hold를 유지했다.
- 운영 기사 단독 보고서 `732b4388-c814-425a-b11c-42674ec1bd31`: 원문 6개, 8개 추출 중 3개 검토, 보도 근거 범위 true 3개, 반증 검색 완료, AI 7호출. 나머지 5개는 미검증이다.
- 두 요청 모두 HTTP 200·공개 GET의 저장 결과 정확 재생을 확인했다. 설정 가로채기 없는 운영 브라우저 1365px/390px에서 가로 넘침·JavaScript 오류가 없고 근거 카드 4+9개·출처 역할을 확인했다. 공개 health 200과 `/marbas` 설정도 확인했다.
- 독립 최종 검토는 운영 인용 **13/13**, 보도 내용 인용 **19/19**, 본문 해시·원래 입력 보존을 확인했다. 자동 **128/128**, 실제 고정 원문 캐시 2→0호출도 검토했다. 운영 관측 약 **58~67초**, 핵심 3개 제한, 키워드의 보류를 포함한 결과이며 전체 정확도·캐시 적중률 증명은 아니다.
- 검증용 API 31319/Vite 5179는 종료했고 운영 `marbas-api`는 유지했다. 최종 점수 **8.4/10**과 같은 2차 사용량은 [기술 감사 기록](./validation/20261115/operational-audit.json)에 보존했다. [UI 보류 요약 회귀](./validation/20261115/ui-safety.json)도 보존했다. 전체 실사용 보고서·개인명·추문 내용은 문서에 복사하지 않았으며 원본은 Git에서 제외한 런타임 데이터에 남긴다. 보고서 GET에는 사용자 인증이 없으므로 UUID를 아는 사람은 내용을 조회할 수 있다. 이 기술 감사 기록은 익명 자료가 아니다.
